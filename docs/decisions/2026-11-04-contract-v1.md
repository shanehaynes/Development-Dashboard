# Contract v1: code-span ids, two actors, boxes as the only state

Date: 2026-11-04 · Status: accepted

## Context

The dashboard derives status from files that agents in other repos write. The grammar must be loose enough to write as prose, strict enough to parse and lint, and stable under parallel edits. The full grammar and lint rules E01–E19 and W01–W07 will live in `contract/SKILL.md` (phase 2); derivation rules R1–R5 arrive in phase 3. This records the choices that shape them.

## Options

- **Position-based ids** (heading order, line numbers) — no ceremony / every insert or reorder silently retargets refs already in claims and PR titles.
- **Declared status lines** (`**Status:**`, State columns) — readable / they rot; see [read-only posture](2026-11-04-read-only-posture.md).
- **`---`-fenced metadata blocks per item plus a JSONL event log** — exact to parse / not what agents write as prose; the log is a second truth and a hot append file.
- **A separate device actor** — a finer queue / device steps need Shane's hands anyway; a third actor splits his queue.
- **The choices below** — prose-first, lintable, merge-friendly / a grammar every session must learn, and a validator to vendor.

## Decision

- **Identity:** a kebab id in the heading's trailing code span (`` ## Phase 2: Refresh script `refresh-script` ``). Frozen once a box is checked; renames go through `- Aliases:`. Title-derived ids are provisional and refused as refs.
- **Actors:** an unlabelled box is any agent's. `**Shane:**` is Shane's alone, optionally qualified `decide`, `approve`, `device`, `account` or `verify`. `**Chrome:**` is an agent in Shane's signed-in Chrome, attended and serial. One actor per box; every irreversible act is its own Shane box.
- **State:** boxes only: `[ ]`, `[x]`, `[-]` (dropped). `[/]` is banned: Apex's stop-gate does not count it as a box, so a milestone whose open work is `[/]` reads complete. No status words or markers. An item is built when it has a box and every box is `[x]` or `[-]` on main. A Shane or Chrome box is ticked only with a `(Shane YYYY-MM-DD)` stamp.
- **Backlog:** `docs/backlog.md`, one line per entry, append-only, `merge=union` (already in `.gitattributes`).
- **Opt-in:** `.claude/dashboard.json` on main marks an adopted repo and names the contract major, 1.
- **Validator:** `contract/lint.mjs`, Node builtins only, vendored to `.claude/skills/dev-dashboard/` with a `VENDORED` stamp and held for Shane in adopting repos. It will run inside each repo's existing gate through a vitest wrapper, so no `package.json` edit; a `--base` ratchet fails only changed lines. In this repo, phase 2 appends `node contract/lint.mjs` to `npm run check` and adds a CI diff step.
- **Join keys:** `[ref]` (`id` or `id.M2`) in the claim intent and the PR title, then the PR's branch, the item doc a lane touches, the branch token, the session name. `[-]` marks a deliberate chore; anything unmatched is Untracked.

## Revisit when

- Ids collide, or renames exceed two a month.
- A second machine appears, or device steps batch badly three times (then a device actor).
- Lint noise starts being ignored.
- Untracked exceeds 20 % of PRs for two weeks.
- The union merge damages the backlog, or it passes about 60 lines.
- A derived status misleads Shane twice in a month where a declared line was right.
