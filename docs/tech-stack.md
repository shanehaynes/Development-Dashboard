# Tech stack

What the dashboard is built on, why, and what would reopen each choice. It answers to [mission.md](mission.md). A new layer, a new runtime dependency or a ruled-out choice coming back is proposed in a PR of its own with the reason; `package.json` dependencies are held for Shane.

Day 0 built the runtime, the UI shell, Vite with the per-checkout port, the test, lint and format tooling, the fixture generator, and CI. The rest is design ([roadmap.md](roadmap.md)): phase 1 adds the GET routes, child processes, sources and the real-versus-fixture split; phase 2 `contract/`; phase 4 the ack route, `blocked.tsv`, the snapshot cache and the live overlay; phase 8 the heartbeat.

## Gate

```bash
npm run check   # tsc -b && vitest run && oxlint && prettier --check .
```

Phase 2 appends `&& node contract/lint.mjs`. Parallel-safe: it starts no server and writes no global path; integration tests will work in temp dirs.

## Deliberately not used

- **Hono**: three routes fit in a Vite middleware; a framework adds a dependency and nothing else.
- **Supabase**: nothing to share, authenticate or store off this Mac.
- **Vercel or GitHub Pages**: never deployed; a hosted copy has no local state to read.
- **A database**: every status is derived per poll; the owned facts fit in an append-only TSV and a cache.
- **SSE or file watchers**: about 100 worktrees against the macOS soft limit of 256 open files; a 3 s poll with ETag meets the 5 s target. Revisit if a snapshot takes over 150 ms or lag shows.
- **Router or state libraries**: one page, a `#/<key>` hash route through `useSyncExternalStore`, and panels that are pure functions of one snapshot.
- **Python**: a second toolchain, and the contract must run inside each adopting repo's Node gate.
- **Emitter hooks in target repos** (Stop, PostToolUse on Chrome tools, UserPromptSubmit): disk already carries these signals, and an event spool is a second source of truth. Revisit when a signal that is not on disk is asked for twice, or the Chrome lock is bypassed twice.
